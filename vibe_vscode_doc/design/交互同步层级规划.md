# 交互同步层级规划

> 文档状态：后续规划与历史验收记录，不代表 PR #1 当前实现。PR #1 的 authority、交付边界、开放 Review 和验收入口以[统一设计文档](pr1_logical_workspace_and_fullscreen.md)为准；本文涉及 Workspace 配置存储、editor working set 和旧服务路径的内容均不能用作当前实现契约。

## 作用域定义

这里的 Workspace 指 vibe vscode Logical Workspace，不是 VS Code 物理 `.code-workspace`。物理 workspace 提供共同的项目成员和服务端配置文件，Logical Workspace 在其内部划分布局、Terminal 和打开的 Session Tab working set；Session catalog 本身保持全局。

同步必须区分三种 authority，禁止让浏览器副本自行裁决共享业务状态：

| 层级 | Authority | 生命周期 | 典型状态 |
| --- | --- | --- | --- |
| 服务端共享 | Remote Logical Workspace State Channel + SQLite | 跨网页、跨机器、跨服务重启 | Workspace catalog 与每个 Workspace 的资源快照 |
| 页面 session | 当前标签页 `sessionStorage` | 标签页内刷新保留，标签页之间隔离 | `activeWorkspaceId` |
| 页面瞬时 | 当前页面内存与 DOM | 刷新即失效 | picker 开关、hover、恢复中的 pending 状态 |

## 跨窗实时同步

以下 confirmed 数据通过远程 committed snapshot event 跨窗实时更新：

- Workspace catalog，包括 ID 与名称。
- 各 Workspace 的最新资源快照数据。
- Terminal 的唯一 Workspace 归属，以及每个 Workspace 打开的 Session Tab references。同一 Session reference 可同时存在于多个 Workspace。

“数据已同步”不等于“立即投影 UI”。其它网页提交语义 mutation 后，本页可以更新内存中的 confirmed snapshot，但不得因此触发 activation、切换当前 Workspace，或即时覆盖本页正在使用的布局和焦点。

## 下次刷新或显式切换时同步

每个 Workspace 的以下状态归属于服务端共享快照，但只在本页刷新恢复或显式激活该 Workspace 时投影：

- 主侧栏、底部面板、辅助侧栏的可见性、尺寸与 active composite。
- Project folder focus。
- 编辑器分组、打开集、active editor 与 focus。
- 终端集合与 active terminal。
- 打开的 Chat / Agent Session Tab references。全局 Session catalog 和 Agent Sessions 侧边栏列表不属于 Workspace snapshot。

刷新恢复必须先从页面 session authority 得到明确的 Workspace ID，再读取该 Workspace 的最新共享快照。所有异步恢复和回写都必须携带 Workspace ID 与 activation sequence；过期结果必须丢弃，禁止读取异步完成时的隐式 current Workspace。

## 编辑器与 Webview 恢复约束

编辑器 working set 是 Logical Workspace 资源快照的一部分。普通文件编辑器可以在打开集变化时立即序列化，但 Webview 的恢复 state 由其内容脚本异步调用 `setState(...)` 产生；“Webview editor 已加入分组”不代表恢复 identity 已经就绪。

工作区编辑器适配层除监听编辑器与分组变化外，还必须监听每个 `WebviewInput.webview.onDidUpdateState`，并复用同一个有界保存入口重新序列化当前投影的 working set。保存前必须校验 projected Workspace 与当前 activation intent 仍一致；恢复过程中不得把中间态反向保存成 confirmed snapshot。

可恢复 Webview 的 state 必须包含目标最小闭包。Markdown 动态预览至少必须保存明确的 `resource`，并可附带 `resourceColumn`、`line` 与 `locked`。历史快照缺少 `resource` 时，reviver 必须拒绝恢复并关闭该旧预览，禁止根据当前编辑器、标题或数组位置猜测文件；用户再次显式打开预览后，新的完整 state 才能进入共享快照。

验收必须分成两个独立阶段：`open` 阶段显式打开预览、等待正文并确认共享 working set 已落盘完整 state；`restore` 阶段使用全新页面且不发送打开命令，仅凭页面 Workspace identity 与服务端最新快照恢复正文。只看到 `Preview README.md` 标签、空 Webview 或错误页都不算恢复成功。

## 页面独占状态

`activeWorkspaceId` 必须页面独占。页面 A 切换 Workspace 不得改变页面 B；页面 B 收到共享配置变更时，只要自己的 Workspace 仍存在，就不得发出 activation event。

同一页面刷新后仍使用原来的 `sessionStorage`，所以会恢复该页面上次选择；新标签页没有既有页面 identity 时，从 catalog 第一项开始。当前 Workspace 被服务端删除是唯一允许配置同步迫使页面改选的情况，此时收敛到 catalog 第一项。

picker、hover、拖拽提示和恢复中的 pending 标记属于纯页面瞬时状态，不进入服务端快照，也不写入页面 selection authority。

Workspace、Project 以及需要选择终端 cwd 的 Quick Pick 打开时，唯一 focused 行必须由当前 authority 派生，不能只设置 `picked` 或依赖列表顺序。Workspace 使用当前页面 `activeWorkspaceId`，Project 与终端 cwd 使用当前 Workspace 的 `projectFolderUri`；新增动作和其它项目不得抢占初始高亮。

## schema 与迁移

共享 schema v2 只保存 `workspaces`，禁止出现 `activeWorkspaceId`。schema v1 的共享 `activeWorkspaceId` 只允许作为升级页面的首次 selection seed；远程 `initialize-if-absent` 成功后不再共享或双写该字段。旧浏览器 `{ counter, source }` envelope 只可作为远程为空时的 migration candidate，不能参与远程 revision 裁决。

验收至少使用两个独立页面 session：分别选择不同 Workspace，在一页修改并保存资源快照，确认另一页不切换；随后刷新另一页，确认它保持自己的 Workspace identity，并恢复该 Workspace 的最新服务端快照。
