# Vibe VS Code v1.135.0-vibe.1

[English](#english) | [简体中文](#简体中文)

## English

This is the first release of **vibe vscode**: a browser-first, long-running development workbench built on Code - OSS. Keep your development environment on an always-on workstation or in the cloud; wherever you are, open a browser, pick up where you left off, and start vibe coding. It does not replace VS Code's editing, terminal, or extension capabilities. It adds stable context management so projects, terminals, and Agent sessions stay continuous across context switches and network interruptions.

The release targets Linux x64 and ships the Web workbench with its remote server in one archive: Node, pinned Caddy 2.11.4, production dependencies, built-in extensions, and verified browser cache chunks. No separate Node/Caddy installation, root, systemd or source checkout is needed to run it. Full installation, optional service setup, upgrade, and rollback steps are in [Install and start](https://github.com/ActivePeter/vibe-vscode/blob/main/docs/install.md); the README has the same quick start.

### What's in this release

Items marked ✅ on the [README roadmap](https://github.com/ActivePeter/vibe-vscode#features-roadmap) are included:

- ✅ **Web-first operation**. Projects, terminals, and Agent tasks run on the server; the browser handles interaction and state projection. No desktop client.
  - ✅ **Cached page loading and resumable downloads** ([#14](https://github.com/ActivePeter/vibe-vscode/pull/14)). Core startup resources are compressed, chunked, verified, and cached in the browser with visible download progress. Reopening the browser reuses cached chunks, interrupted downloads resume only the missing chunks, and new releases reuse unchanged content.
  - ✅ **Sign-in required** ([#15](https://github.com/ActivePeter/vibe-vscode/pull/15)). Every hosted HTTP request and WebSocket handshake must pass sign-in before it reaches any VS Code route. The first visitor registers the single administrator account, after which registration closes. Sessions survive server restarts, renew while in use, and can be revoked from the Accounts menu or the Command Palette (`vibe-vscode: Sign Out`). Authentication is embedded in the remote server with Node's built-in SQLite; Caddy enforces it at the gateway with `forward_auth`. Design: [login_authentication.md](https://github.com/ActivePeter/vibe-vscode/blob/main/vibe_vscode_doc/design/login_authentication.md).
- ✅ **Logical Workspace**. Create and switch logical workspaces from the status bar or Command Palette without reloading the page. Layout, editor working sets, and the workspace catalog are stored in remote SQLite, so any page shows the latest state after a refresh or reconnect. Terminals belong to the workspace that created them and move between foreground and background without being closed; a stable terminal ID survives PTY reconnection and page restoration.
- ✅ **Project Context**. Select or add a project folder inside one multi-root workspace. Explorer focuses the project root and Source Control shows only that project's repositories, while open editors, terminals, and sessions stay intact. Separate status-bar entries show the current Workspace and Project.

### Getting started

```bash
curl -fsSL https://github.com/ActivePeter/vibe-vscode/releases/download/v1.135.0-vibe.1/install.sh | bash -s -- --tag v1.135.0-vibe.1
~/.vibe-vscode/current/bin/vibe-vscode start --origin https://dev.example.com:18080
# Open https://dev.example.com:18080; register the administrator, then add projects in the workbench.
```

Replace the example hostname with your browser-visible hostname or IP. Without your own certificate, trust the Caddy root certificate printed at startup; Ctrl-C stops both components. Repeat `--origin` for multiple entries. Persistent configuration, optional `vibe-vscode systemd`, health checks and rollback: [Install and start](https://github.com/ActivePeter/vibe-vscode/blob/main/docs/install.md) · [README quick start](https://github.com/ActivePeter/vibe-vscode#features-roadmap).

### Upgrade notes

- First release, nothing to migrate. Keep `<state-root>/auth` (the SQLite database and signing secret) and `<state-root>/server` outside the release tree so future upgrades and rollbacks preserve accounts, sessions, and settings. Losing the `auth` directory invalidates every session and reopens registration for the first visitor.
- Caddy is bundled. Only Caddy listens on the public port; the backend stays on a private Unix socket. The installer preserves releases and state; upgrading or rolling back changes the selected version but requires a separate restart.
- The first person to open the address becomes the administrator. Restrict access until that account exists.
- `--origin` (or comma-separated `VIBE_VSCODE_ORIGIN` in the state directory's `vibe-vscode.env`) lists the exact HTTPS addresses users type into the browser, including non-default ports. Unlisted hosts cannot submit login forms; no domain is required.

### Not in this release

- 🚧 Non-blocking remote connectivity (status-bar reconnect instead of a modal interruption) is in progress.
- ⬜ Chat / Agent session-tab working sets per logical workspace, the fullscreen session management panel, document-driven development, and Codex Agent-first interaction are planned.
- Only Linux x64 packages are built. The Electron desktop product is a non-goal; upstream Electron sources remain only to ease synchronization.

### Known issues

- Linux x64 only.
- With the Simplified Chinese language pack installed, the Accounts menu entry "Sign Out" is shown in English until the language pack carries this key; the login, registration, and sign-out pages themselves are bilingual.
- Cached startup chunks require a secure context (HTTPS or localhost) plus the browser's `DecompressionStream` and `crypto.subtle`; the startup page explains when either is missing.

### Verification

Every release is built from one tagged commit that has passed Vibe CI: type checking, ESLint, hygiene, dependency layers, build tests, product-area regression tests, the Node authentication suite, the real-Caddy authentication boundary test, and packaging plus installed-runtime smoke tests for both bundled and minified Web Server variants. The published archive is also installed and started with local-CA and provided TLS before publication; cleanup, state preservation and lock contention are checked.

## 简体中文

这是 **vibe vscode** 的第一个版本:一个基于 Code - OSS、面向浏览器、可长期运行的开发工作台。把开发环境放在常驻工作站或云端,无论身在何处,打开浏览器就能接着上次的工作继续 vibe coding。它不替换 VS Code 的编辑、终端和扩展能力,而是在其上增加稳定的上下文管理,让项目、终端和 Agent 会话在切换与网络波动中保持连续。

本版本面向 Linux x64,一个压缩包里包含 Web 工作台与远程服务器:Node、固定版本 Caddy 2.11.4、生产依赖、内置扩展和已校验的浏览器缓存分块,运行时不需要单独安装 Node/Caddy,也不需要 root、systemd 或检出源码。完整的安装、可选服务化、升级与回滚步骤见[安装与启动文档](https://github.com/ActivePeter/vibe-vscode/blob/main/docs/install.md);README 里有同样的快速开始。

### 本版本包含

[README 路线图](https://github.com/ActivePeter/vibe-vscode/blob/main/README_CN.md#功能路线图)中标为 ✅ 的能力都已包含:

- ✅ **Web 优先运行**。项目、终端和 Agent 任务运行在服务端,网页负责交互与状态投影,无需桌面客户端。
  - ✅ **页面加载缓存与续传**([#14](https://github.com/ActivePeter/vibe-vscode/pull/14))。核心启动资源压缩、分块并校验后缓存在浏览器中,加载时显示下载进度。重新打开浏览器复用缓存,下载中断后只补齐缺失分块,版本更新时复用未变化的内容。
  - ✅ **登录后才能访问**([#15](https://github.com/ActivePeter/vibe-vscode/pull/15))。所有托管的 HTTP 请求和 WebSocket 握手在到达任何 VS Code 路由之前必须先通过登录。第一个访问者注册唯一的管理员账号,之后注册关闭。会话在服务重启后仍然有效,使用中自动续期,可在 Accounts 菜单或命令面板(`vibe-vscode: Sign Out`)退出。认证内嵌在远程服务器进程中,使用 Node 自带的 SQLite;Caddy 在网关用 `forward_auth` 强制执行。设计文档:[login_authentication.md](https://github.com/ActivePeter/vibe-vscode/blob/main/vibe_vscode_doc/design/login_authentication.md)。
- ✅ **Logical Workspace(逻辑工作区)**。从状态栏或命令面板创建、切换逻辑工作区,无需刷新页面。布局、编辑器工作集和工作区目录保存在远程 SQLite,任何页面刷新或重连后都看到最新状态。终端归属于创建它的工作区,切换时只在前后台之间迁移而不会关闭;稳定的终端 ID 贯穿 PTY 重连与页面恢复。
- ✅ **Project Context(项目上下文)**。在同一个多根工作区内选择或添加项目目录。Explorer 聚焦项目根目录,Source Control 只显示该项目内的仓库,已打开的编辑器、终端与会话保持不变;状态栏分别显示当前 Workspace 与 Project。

### 升级须知

- 首个版本,无需迁移。把 `<state-root>/auth`(SQLite 数据库与签名 secret)和 `<state-root>/server` 放在 release 目录之外,后续升级与回滚才能保留账号、会话与设置。`auth` 目录丢失会使所有会话失效,并对第一个访问者重新开放注册。
- Caddy 随包提供;公开端口只由 Caddy 监听,后端只在私有 Unix socket 上。安装器保留历史版本与状态;升级和回滚只切换选中版本,需要另行重启。
- 第一个打开地址的人即成为管理员,请在该账号创建前限制访问。
- `--origin`(或状态目录 `vibe-vscode.env` 中逗号分隔的 `VIBE_VSCODE_ORIGIN`)列出用户在浏览器输入的完整 HTTPS 地址,含非默认端口。未列出的主机不能提交登录表单,不要求拥有域名。

### 本版本不包含

- 🚧 非阻塞的远程连接体验(用状态栏重连状态替代模态打断)进行中。
- ⬜ 逻辑工作区级别的 Chat / Agent Session Tab 工作集、全屏会话管理面板、文档驱动开发、Codex Agent 优先交互为计划项。
- 只构建 Linux x64 包。Electron 桌面端不是目标,保留上游 Electron 源码仅为便于同步。

### 已知问题

- 只提供 Linux x64。
- 安装了简体中文语言包时,Accounts 菜单里的 "Sign Out" 暂显示英文,直到语言包收录该键;登录、注册、退出页面本身是双语。
- 启动缓存分块需要安全上下文(HTTPS 或 localhost)以及浏览器的 `DecompressionStream` 与 `crypto.subtle`;不满足时启动页会给出说明。

### 验证

每个版本都由一个通过 Vibe CI 的 tag 提交构建:类型检查、ESLint、hygiene、依赖分层、构建脚本测试、按产品区域发现的回归测试、Node 认证测试、真实 Caddy 的认证边界测试,以及 bundled 与 minified 两种 Web Server 包的打包与安装启动测试。正式附件也在发布前经安装器安装,用自签和自有 TLS 启动,验证进程清理、状态保留与锁冲突。
